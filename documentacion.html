Resumen técnico

unDEAenunaCaja es un simulador de Desfibrilador Externo Automático (DEA) y Semiautomático (DESA) para capacitación en reanimación. Una persona instructora conduce la simulación con botones; la aplicación reproduce las indicaciones de voz del equipo, muestra el texto en pantalla y marca los 2 minutos de RCP entre análisis de ritmo.

Característica Detalle
Tipo Aplicación web estática, instalable como PWA y utilizable sin conexión
Stack HTML5, CSS3 y JavaScript (ES6+) sin frameworks, sin dependencias y sin paso de compilación
APIs web HTMLAudioElement, requestAnimationFrame, Service Worker, Cache API, Web App Manifest
Modelo de ejecución Máquina de estados dirigida por datos: 17 estados definidos en el objeto historia, interpretados por un único motor
Salida Audio MP3 pregrabado (13 archivos, unos 1,3 MB; metronomo.mp3 es el 35 %) y texto en pantalla
Persistencia Ninguna de la simulación (el estado vive en memoria). El service worker guarda los recursos en caché
Compatibilidad Chrome, Edge, Firefox y Opera en Windows, Linux y Android; Safari en iOS (limitado)
Licencia GPL v3
Repositorio github.com/Ggaita/undeaenunacaja


  1. Tocá Comenzar y elegí el modo: Automatico o Semiautomatico.
  2. El equipo brinda indicaciones por voz. Quien instruye responde con los botones según lo que hacen los participantes:
    verde cuando lo hacen bien,
    rojo cuando no, iniciando un bucle.
  3. Al tener que iniciar maniobras de RCP aparece la cuenta regresiva de 2 minutos. Al terminar, el equipo vuelve a pedir el análisis de ritmo.
  4. Reiniciar vuelve a la pantalla de inicio en cualquier momento, sin recargar la página.

Metrónomo y temporizador

En las pantallas metronomo y metronomoAutomatico se reproduce metronomo.mp3, que dura 2 minutos y marca el ritmo de las compresiones. Mientras suena aparece la barra de progreso y el tiempo restante (MM:SS).

La cuenta regresiva sale del propio audio: restante = duración − tiempo actual. Si el navegador todavía no conoce la duración, usa 120 segundos. El color de la barra cambia según el tiempo que queda:


Tiempo restante Color
Más del 50 % Verde #00c853
Entre 50 % y 20 % Amarillo #ffd600
Menos del 20 % Rojo #d50000


Cuando el audio termina (evento audio.onended) se oculta el temporizador y la aplicación pasa sola a la pantalla de análisis de ritmo del modo en curso.

Arquitectura

El diseño separa los datos (qué dice y a dónde va cada pantalla) del motor (cómo se reproduce y se dibuja). Agregar o cambiar pantallas es editar un objeto, sin tocar la lógica; la excepción son los dos metrónomos, que están escritos en el motor (ver Extensión).

Capa Dónde Responsabilidad
Presentación index.html, documentacion.html, styles-documentacion.css, styles.css, reset.css DOM fijo; los botones de respuesta se crean dinámicamente en cada estado

Motor cambiarEstado, reproducir, temporizador Interpreta un estado: reproduce el audio, escribe el texto, crea los botones y controla el temporizador

Recursos src/, icons/ Audios, logos, bandera e íconos

Ciclo de vida de la página

  1. Carga: se muestra el botón Iniciar. Todavía no suena nada porque los navegadores exigen un gesto del usuario antes de reproducir audio.
  2. Se registra el service worker (service-worker.js) y se instala la caché.
  3. Iniciar ejecuta empezar(): oculta ese botón, muestra #opciones y #btnReiniciar, y entra en el estado inicio.
  4. Cada botón de respuesta llama a cambiarEstado(siguiente). Las únicas transiciones sin botón son las de fin de metrónomo, que dispara el evento ended del audio.

Qué hace cambiarEstado(clave)

  1. Guarda estadoActual = clave y obtiene historia[clave]. Si la clave no existe, el nodo es undefined y la función lanza un error: la aplicación deja de responder.
  2. Reproduce nodo.audio desde el segundo 0.
  3. Vacía #opciones y escribe nodo.texto con textContent (cadena vacía si el nodo no tiene texto).
  4. Si la clave es metronomo o metronomoAutomatico: muestra el temporizador y define audio.onended para volver al análisis de ritmo de su modo. En cualquier otro estado oculta el temporizador y pone audio.onended = null.
  5. Crea un <button> por cada opción, con su clase CSS, y le asigna onclick = () => cambiarEstado(op.siguiente).

Modelo de datos y extensión

Cada estado es una entrada del objeto historia. La clave es el identificador del estado.

nombreDelEstado: {
  audio: "./src/archivo.mp3",
  texto: "Texto que se muestra",
  opciones: [
    { texto: "Sí", siguiente: "otroEstado", clase: "btn-verde" },
    { texto: "No", siguiente: "nombreDelEstado", clase: "btn-rojo" }
  ]
}
Campo Tipo Obligatorio Regla
audio string sí Ruta relativa a un .mp3. Si el archivo no existe, el estado igual avanza pero no suena.
texto string no Se muestra tal cual (sin HTML). Si falta, se limpia el texto anterior.
opciones array sí Puede ser vacío. Solo los estados de metrónomo terminan por el fin del audio; un estado vacío cualquiera dejaría la simulación sin salida, salvo Reiniciar.
opciones[].texto string sí Rótulo del botón
opciones[].siguiente string sí Clave de un estado existente. Si apunta al mismo estado, la indicación se repite.
opciones[].clase string no btn-opciones, btn-verde o btn-rojo. Sin clase, el botón es azul.

Agregar o modificar una pantalla

  1. Grabar el audio en MP3 y guardarlo en src/.
  2. Agregar el estado en historia y apuntarle un botón desde otro estado.
  3. Agregar la ruta del audio a urlsToCache en service-worker.js.
  4. Subir CACHE_NAME (por ejemplo a dea-simulador-v2) para que los dispositivos descarguen la versión nueva.
  5. Validar el grafo con el script de la sección Verificación.

Agregar un modo nuevo

Hoy exige tres cambios: los estados del modo, un botón eninicioOpciones y un caso en cambiarEstado para el metrónomo. Para no tocar el motor, se podría agregar un campo alTerminar a cada estado de metrónomo, con la clave del estado que sigue.



metronomo: {
  audio: "./src/metronomo.mp3",
  texto: "Espere los 2 minutos para analizar el ritmo nuevamente",
  opciones: [],
  temporizador: true,
  alTerminar: "analisisRitmo"
}

// En cambiarEstado: reemplaza las dos ramas por nombre
if (nodo.temporizador) {
  iniciarTemporizador();
  audio.onended = () => {
    ocultarTemporizador();
    cambiarEstado(nodo.alTerminar);
  };
} else {
  ocultarTemporizador();
  audio.onended = null;
}

service-worker.js

Evento Comportamiento
install Abre la caché CACHE_NAME y ejecuta cache.addAll(urlsToCache). Es atómico: si un solo archivo falla (404, red), la instalación entera falla y no queda nada guardado. No llama a skipWaiting(): una versión nueva espera hasta que la persona acepte la actualización.
activate Borra toda caché cuyo nombre sea distinto de CACHE_NAME. No llama a clients.claim(): en la primera instalación, la pestaña abierta no queda controlada hasta recargar.
fetch Cache-first para todo: caches.match(request).then(r => r || fetch(request)). No hay caché dinámica: lo que no está en el precaché se pide a la red y no se guarda (por ejemplo /favicon.ico).
message Si el dato es "SKIP_WAITING", ejecuta self.skipWaiting().

Flujo de actualización

  1. Se publica una versión con CACHE_NAME distinto. El navegador detecta que service-worker.js cambió y lo instala en segundo plano (nueva caché).
  2. Cuando el worker nuevo queda installed y ya hay uno controlando la página, index.js muestra el cartel «Nueva versión disponible».
  3. Actualizar envía SKIP_WAITING; el worker nuevo se activa y borra la caché vieja.
  4. El evento controllerchange recarga la página con los recursos nuevos.

Procedimiento para publicar una versión

  1. Modificar los archivos. Si se agregan, renombran o quitan recursos, actualizarurlsToCache.
  2. SubirCACHE_NAME.
  3. Publicar y abrir la aplicación con la versión anterior ya instalada: debe aparecer el cartel de actualización.
  4. Revisar en las herramientas del navegador:Application → Service Workers(estado del worker) yCache Storage (28 entradas en la caché nueva, y sin la vieja).
  5. Probar sin conexión: activar modo avión, recargar y recorrer un modo completo.

Glosario

Término Significado
